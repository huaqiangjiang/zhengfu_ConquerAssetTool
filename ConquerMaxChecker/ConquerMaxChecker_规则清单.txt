征服MAX模型检查器 — 统一规则 v0.2.2
日期：2026-09-21；适用：3ds Max 2015；外部工具：ConquerAssetTool 0.2.2
规则依据：整个界面功能1.emmx（含3张参数截图）优先于旧清单与旧代码。
用户补充：模型归零暂定为“模型整体移动到世界原点 [0,0,0]”。

一、状态与处理范围
检查只读；通过、不通过、执行报错、按规则跳过分别表达。
修改与生成操作给出实际结果；报告文件存在不能当作转换成功。
生产范围为场景几何，可勾选仅选中模型；基础体、插件临时对象、骨骼和明确标注 ConquerReference=true 的参考对象除外。
环境与场景清理仍是全场景操作，按规则保留组。
没有实际挂到生产模型的材质编辑器贴图不进入转换队列。

二、场景环境
显示单位 Generic；系统单位 Inches；系统比例 1.0。
背景 color 127 127 127；环境光 color 0 0 0；环境染色 color 255 255 255。
关闭 Gamma/LUT；生产渲染器为默认扫描线；产品级渲染，不使用迭代或 ActiveShade。
按导图渲染截图：区域（Area）过滤器，过滤器大小 1.5，抗锯齿与过滤贴图开启。
相机、灯光、辅助对象、骨骼与变换关键帧属于场景清理；组头、组成员不按普通辅助对象删除。
骨骼按对象类型识别，不凭名称包含 bone/bip 删除普通模型。

三、模型
名称严格为小写 v_body；保持显示；线框黑色；最终为 Editable Poly。
光滑组统一为 1；重置法线并塌陷；必要时 Reset XForm；整体位置归零。
废点自动清理；零面积面、大于四边的面报告为待处理，不自动猜测拓扑修改。
基础体只作观察，按 baseObs_* / baseObsMat_* 恢复识别；不参与生产输出。

四、材质与颜色贴图
生产材质 Standard；不含子材质；名称与实际颜色贴图基础名一致。
双面开启；自发光数量 100；关闭自发光颜色。
多维或嵌套材质不能无条件挑第一个子材质；保留原材质，提示按实际材质分离对象后再修复。
颜色贴图必须为实际存在的 TGA Bitmap；不以更改扩展名冒充格式转换。
其他格式仅在存在真实同名 TGA 时重链，否则保留原引用并报错。
通道 1；关闭 Real World Scale；偏移 0；平铺 1；关闭镜像、开启 U/V 平铺。
颜色贴图截图：单通道 RGB 强度；RGB 通道输出 RGB；Alpha 来源为无；预乘 Alpha 关闭。

五、Alpha 与透明贴图
有 Alpha：透明贴图为颜色贴图的独立副本，启用不透明度贴图；不能共用实例。
透明贴图截图：单通道 Alpha；RGB 通道输出 Alpha 作为灰度；来源为图像 Alpha；预乘 Alpha 开启。
无 Alpha：透明贴图为空并关闭。
读取失败：保留原透明设置，明确报告读取问题。
重复修改不重新创建已经正确的透明 Bitmap。
去除路径只保留文件名；需先确认真实来源存在且可解析。不得用其他资源包的同名文件替代明确引用。
材质修复和全修改都执行去路径；没有执行错误时保存 MAX，保存失败单独报告。
材质编辑器按当前生产材质清空并重新拾取一次。

六、资源文件夹
必须有独立资源根目录；不能直接把桌面或磁盘根目录当作资源包。
根下 C3、MAX、设计稿、渲染图；渲染图下有界面文件夹。
MAX：.max、.tga。C3：.c3、.dds、.png、.uoc。
设计稿：.jpg、.png、.psd；已经在设计稿中的有效图片原位保留。
渲染图：.jpg；渲染图/界面：.png。
根部散文件：MAX/TGA 归 MAX；C3/DDS/UOC 归 C3；PSD 归设计稿；JPG 归渲染图；PNG 归界面。
不相关文件只能位于当前资源根下，不扩展到资源包父目录。
当前打开的 MAX 由 MAX 自己另存，外部整理器不移动其打开源文件。
用户补充：MAX 文件夹只保留当前修改后的一个 MAX。
同名目标先备份再更新，不追加数字后缀；其他旧 MAX 校验备份成功后移出资源包。
旧版本保存在 %LOCALAPPDATA%/ConquerMaxChecker/backups/整理前旧MAX；备份失败保留旧文件并报告失败。
必须先由 MAX 保存当前修改后的文件，外部工具不能猜测应保留哪个 MAX。
整理成功后当前场景路径切换到 MAX 文件夹，后续普通保存更新同一份文件。
仅选择 MAX 子目录不向上整理其同级目录。
文件夹检查仍可报告未满足规范的项目，但不把“不通过”当成工具执行失败。

七、TGA 转 PNG / DDS
仅转换当前生产模型真实引用的 TGA。源文件缺失、同批次输出重名时明确失败。
统一使用同版本独立 EXE，不依赖系统 Python，不使用另一台电脑的硬编码路径。
输出明确指定为当前资源根的 C3；文件基础名与 TGA 相同。
PNG：直接读 TGA，保留尺寸、RGB 与 Alpha；保存后回读逐像素验证；无 Alpha 的源保存 RGB PNG。
DDS：无 Alpha 使用 DXT1，有 Alpha 使用 DXT5，默认 2 层 Mipmap，保留原尺寸并检查输出头和数据。
先写临时文件并校验，再替换同名输出；失败保留原来的有效输出。
不删除或修改源 TGA，不更改 MAX 贴图引用。
外部检查以“同名 TGA 配 DDS 或 PNG”作为配套规范，PNG 不再被强制要求另有 DDS。

八、C3 导出
逐个生产对象孤立导出，排除基础体；名称取实际颜色 TGA 基础名。
导出前检查 UV 通道1，缺失时明确报告，不进入会抛系统异常的原生导出器。
同名旧 C3 允许被新结果替换；同一批多个对象产生同名输出则先停止，防止物件相互覆盖。
先导出临时 C3，确认新文件存在且非空，再替换旧 C3；失败不能因旧文件存在误报成功。
C3 导出只输出 C3，不顺带复制 TGA、DDS 或 PNG。
只清理本次在目标 C3 目录生成的新 C3Exp*.txt / *.log；不扫描桌面或其他工程，不关闭用户的记事本。
任一导出失败，汇总已成功数量与失败对象，依赖该结果的一键流程停止。

九、预览与界面出图
场景预览：512×256 JPG，保存到渲染图，命名为 MAX基础名_渲染图.jpg。
UI：逐物件输出透明 PNG，按包围盒选 600×800 或 800×600；左转30度、俯视15度；约5%边距。
UI 输出到渲染图/界面，扫描顺序 1.png、2.png……；_F 贴图对象跳过且不占编号。
基础体与临时节点不输出；结束恢复原场景选择、隐藏、渲染器、环境与视口。
部分 UI 失败应显示部分完成与失败清单；全部因 _F 规则跳过不是转换错误。

十、一键流程与恢复
执行：位置检查 → 自动备份 → MAX全修改 → 保存到MAX → 文件夹整理 → 外部检查 → DDS → C3 → JPG预览 → UI PNG。
普通检查不通过不阻断；真实执行错误、缺失源贴图、保存失败或输出失败停止后续依赖步骤。
独立进度窗保持主界面显示；运行时禁用重复操作，可请求在当前阶段完成后停止。
每次修改前在 %LOCALAPPDATA%/ConquerMaxChecker/backups 保存场景副本；失败则不开始修改。
材质与环境修改保留其撤销操作；模型/全修改因塌陷等操作清空撤销历史，使用备份恢复。
每次外部操作使用独立报告目录，避免旧报告导致假成功；面板显示问题详情和输出详情。
